## 任务 A：第二栏宽度与响应式布局（UI-LAYOUT-02）

真实故障：第二栏（Files/Find 功能面板）宽度不足，工具图标、标签和文件名称出现遮挡/省略，顶部按钮与旁边内容挤压。

要求：
1. 重新核查三栏宽度管理，不要只靠加宽单一固定 dp 数值。实现第二栏**可拖动改变宽度**及合理初始宽度、最小宽度约束与状态持久化（具体尺寸根据平板实际 dp 与断点测得后确定）；编辑区也不得被挤到不可用。
2. 响应式测量组合和字体放大。窄窗口/竖屏优先让文件栏抽屉或折叠，同时提供恢复入口。
3. Files/Find 工具栏使用随宽度自适应排版、图标溢出菜单、可读工具提示，杜绝文字裁剪、触控目标重叠与不可访问动作。长文件名可省略但应有完整名称可访问途径。
4. 用户调节底部终端高度后仍保持三栏稳定。视觉主题、终端底部位置、顶栏 Run / Debug / Overview 相邻关系不变。
5. 至少覆盖 10~13 英寸 Android 平板横屏、竖屏、分屏，Android 字体缩放及触屏/鼠标拖拽检查。

## 任务 C：Files 与 Find 搜索职责清晰化（UI-SEARCH-02）

当前 Files 有 `Search files / folders`，Find 有 `Search in files`。用户发现两处含义重叠，不清楚差异。

要求：
1. 先阅读具体搜索代码，判断它们是否确实分别是文件名/目录名查找与文件内容全文搜索，不能凭截图认定底层逻辑重复。
2. 推荐保留两种**能力**但统一搜索产品模型：Files 侧边栏只提供轻量的**文件名/目录名过滤**（明确标注“筛选文件名/文件夹名”）；Find 作为**统一完整搜索**入口，支持“文件/目录名称”和“文件内容”两个清晰的模式或范围切换，并合理复用同一搜索状态/核心接口。若底层是同一操作则去掉重复 UI，避免两套实现。
3. Find 默认项、搜索范围、大小写、正则等选项应符合实际功能；不应仅改文字造成误导。
4. 搜索结果选择/跳转、清空、当前目录范围、中文文件名、Project 与无 Project 场景都要验证；切换 Files/Find 不应有旧结果泄漏或重复无意义计算。

## 任务 E：中文包采用 .suik 注入（I18N-SUIK-01）

用户要求：软件目前缺少中文，**未来要以可安装的 `.suik` 扩展包方式注入简体中文语言资源**，而不是在主程序内强写死整套中文 UI。

本轮需要：
1. 核查 Core API 3 和现有 `.suik` 的能力边界；设计并实现向后兼容的受权限/Schema 约束的 `localization`（或等价）声明/资源提供器，包括 locale、命名空间、资源键、占位符/复数、fallback English、版本/依赖校验、签名与启停生命周期。

3. 中文包本身为**独立可安装、可卸载的官方 `.suik`**，与 Java/C/C++/Python Kit 不同，是通用本地化功能 Kit，不应滥用语言运行环境或项目工具链；不要要求 Python/JDK 等依赖。
