# sui-code v0.5.3 简体中文扩展包正式实现 — Codex Cloud 工作任务

## 任务背景（来自真实平板反馈）
- 用户已在 ARM64 Android 16 平板上确认 v0.5.2 **启动闪退问题不存在**；立即将下一项最高优先级切换到**完整、可使用的简体中文本地化扩展包**。
- 原 v0.5.1 做了 Core API4 localization 但仅实现 34 个公开 UI 字符串键（见 `core/native-packages/.../Localization.kt::UiTextKeys.english` 和 `docs/specifications/schemas/localization-resources.schema.json`），`docs/specifications/examples/zh-hans-kit/resources/i18n/zh-Hans.json` 只有 12 条翻译；示例包 `dev.suicode.example.zh-hans` 明确不是完整语言包。**不得把原示例伪装成正式中文扩展包**。
- 基线 `sui-code/v0.5.2-startup-recovery` / `7275179bd483b1587113b76d50f8d23e202a0d87`。本任务独立分支 `sui-code/v0.5.3-zh-hans-kit` 已创建，直接在此分支开发。保护 main、历史交付和原 APK。

## 必须交付的成果
1. **真实可安装的简体中文语言包**，建议 `sui-code-zh-hans-1.0.0.suik`，独立于 APK 和 Java/C++/Python Kit，默认不安装、不自动启用、不依赖 Ubuntu/JDK/Python/GCC。
2. **主程序本地化覆盖扩容**：清理各主页面直接硬编码的普通用户可见英文，全部改为 Core 可维护资源键，并让 API4 `ui.localization` Kit 可翻译。仅添加 34 项翻译 JSON 不构成完成。
3. **兼容 APK**：由于主程序需新增 UI 键及绑定，构建一个覆盖安装的 v0.5.3 ARM64 APK（包名 `dev.suicode.ide.debug`、原签名、versionCode>1070805），但本轮仍保持图标原样、启动路径修复不回退。
4. **Android 实际端到端验证**：安装语言包 -> 用户确认权限 -> 在 Packages / Interface language 选“简体中文” -> UI 即时换语言 -> 重启保存选择 -> 禁用或卸载语言包逐键回退英文 -> 重新启用恢复。
5. 交付至少两个独立文件（一个 APK、一个可安装 .suik），分别带 SHA-256、版本/签名状态、安装步骤、成功 Actions 链接和 Artifact；不要求用户反复安装阶段包。Android APK 和 suik 不要捆绑成无法独立管理的单一内置语言。

## 覆盖范围与翻译质量
- 先全面盘点普通用户界面中所有硬编码英文（Compose 文本、Toast/Snackbar、空状态、文件操作/菜单、Settings、Project、Files、Find、Languages、Packages、Kit 安装和授权、状态/错误显示、Run/Build/Test、Debug、Overview、终端页签、顶部/底部导航、导入导出、回收站和对话框），建立 `locale-key-audit.md` 中 source location -> resource key -> zh-Hans 翻译 ->覆盖情况清单；加静态扫描/测试防止后续新增常量遗漏。
- 优先**普通使用路径完整**，达到肉眼可见的 UI 简体中文化，而不仅是导航栏翻译；其余独立开发者工具/高级面板必须如实列成缺口，不得宣称“全汉化”。
- 技术专有名词如 Java、C++、Python、LSP、DAP、IDE Kit、Ubuntu、GitHub、JDK、Maven、clangd、debugpy、文件真实路径、编译器日志、用户源代码、真实文件名、插件作者自带文字不翻译或不强制翻译。使用简洁统一的中文 UI 术语：文件、查找、语言、扩展包、设置、项目、运行文件、调试、终端、概览、构建、测试、依赖、安装、禁用、卸载、文件名筛选、文件内容搜索。
- 中文界面必须适配第二栏自适应宽度、按键、截断、弹窗、字体缩放、横竖屏，不能被“翻译后字数改变”引起的溢出破坏。
- 新增英文默认键及中文翻译一一对应，所有带参数字符串的参数类型/集合一致；动态字符串使用安全的资源格式化，不允许直接将用户路径插入资源键或当作代码解释。需要复数/变量语义时按 API 可兼容扩展，保留英文回退。
- **保留安全边界**：API4 不允许未经信任的资源覆盖安全/权限/签名提示；不要用中文包绕开签名或授权。对于不能通过普通 `.suik` 资源覆盖的安全关键文案，在审核清单明确标注“宿主受保护英文文案”，不要伪装成已翻译，更不要悄悄改变授权语义。
- 当前每包资源限 64 KiB / 当前 Schema 最多 34 键，若扩容后达到限制，应有合理的多资源方案/版本兼容策略，不能放宽安全校验到任意文件访问、HTML/JS注入。更新生产验证器、Schema、SDK、示例、离线打包工具与测试；旧 API4 包/只提供 12 键的示例仍能正常安装并对缺失键回退英文。不得要求清包数据。
- 包作者签名：优先使用已存在、可用且安全的官方签名流水线；若无官方私钥/授权签名途径，应交付明确标注“未签名/需用户确认来源”的有效可安装包，**不得伪造官方签名或称官方已签名**。包可用性优先于来源标签。

## 关键启动稳定性要求：v0.5.1 曾严重闪退
- v0.5.1 因 Android ICU 对 `\{([a-z][a-zA-Z0-9]*)}` 中未转义尾括号拒绝，触发 `PatternSyntaxException`，默认英文首屏即崩溃。v0.5.2 将其改成平台独立的字面占位符扫描。**不得恢复这个正则或引入同类 JVM 可过、Android ICU 不可过的表达式**。
- 扩容成数百个中文/英文键时：空语言、缺失包、损坏包、旧 API3 Kit 与新增包共存、坏偏好、冷启动、重复打开、切换中文、切回英文，全部必须在 Android 16 模拟器实测。若可以测试 ARM64 原生更好；x86_64 AVD + ARM64 bridge 不能冒充真实 ARM64 平板。
- NativeLocalizationProvider、NativePackageHost 初始化、偏好异常回退、SuiStartup 诊断保持稳定，不能在语言包无效时让主界面退出。对异常保留日志，禁止大范围无条件吞异常。
- 不改变 PRoot、Ubuntu、现有语言环境、已经安装的插件/Kit/Project、文件、IDE 二栏拖动、Files/Find 逻辑、Run/Debug/Overview、底部终端。保留同包身份、签名、递增 versionCode 以便覆盖升级，禁止卸载/清数据。
